# Кандидатогенерация для категории услуг

Кандидатогенерация происходит в два этапа:

1. **Отбор кандидатов** (`candidate_generation.ipynb`) — быстрый, эвристический отбор до 500 кандидатов на запрос из полного корпуса. Цель этапа — высокий Recall@500 (почти все релевантные объявления должны попасть в пул), точный порядок внутри пула не важен.
2. **Переранжирование** (`reranking.ipynb`) — CatBoost переупорядочивает те же 500 кандидатов и обрезает до 50.

## Ноутбуки

### `feature_analysis.ipynb`
Анализ числовых, бинарных и категориальных признаков.

### `candidate_generation.ipynb`
Строит до 500 кандидатов на каждый запрос, считает Recall@k (k = 50, 100, 200, 250, 500) на локальной валидационной выборке, генерирует кандидатов для теста.

### `reranking.ipynb`
Обучает CatBoost на кандидатах, сгенерированных тем же пайплайном для размеченных запросов `train.parquet`, сравнивает Recall@50 реранкера с RRF-бейзлайном, применяет обученную модель к тесту, сохраняя `answer.csv`.

## Методы

**Отбор кандидатов** — 6 фильтров. Первый — жёсткий (отсекает
объявления совсем), остальные пять — мягкие, дают каждый своё число, и
объединяются весами через Reciprocal Rank Fusion:

1. **Категория (жёсткий).** `item_category_id == search_category`;
   отключается для `search_category == 0` ("категория не выбрана") — иначе
   кандидатов вообще не найдётся.
2. **`coverage(q, d)` параметров.** Доля токенов `search_infm_params_text`,
   найденных в `item_infm_params_text`: точным совпадением ИЛИ (если
   точного нет) семантически — эмбеддинг токена запроса против эмбеддинга
   параметров объявления, `multilingual-e5-large`; порог подобран на парах
   из `train.parquet`. Точное совпадение покрывает почти всё (словарь
   параметров контролируемый), семантика — редкий fallback.
3. **`coverage(q, d)` текста.** Точное совпадение токенов запроса в
   заголовке и описании объявления.
4. **E5-похожесть текста.** Косинусная близость эмбеддингов запроса и
   заголовка+описания объявления — отдельный от (3) сигнал, ловит
   перефразировки, которые точный `coverage` пропускает.
5. **Локация.** Точное совпадение `location_id` либо оценка, убывающая с
   расстоянием до центроида координат нужной локации.
6. **Микрокатегория.** Косинусная близость эмбеддинга запроса к
   эмбеддингам объявлений той же микрокатегории.

Все токенизаторы используют **лемматизацию** (`pymorphy3`).

**Переранжирование** — CatBoost с функцией потерь `YetiRank` (listwise
learning-to-rank): для каждого запроса корректно
упорядочивает его кандидатов. Признаки — сырые скоры всех пяти сигналов
кандидатогенерации плюс `rrf_score`/`rrf_rank`, рейтинг, логарифм числа
отзывов и цены, контактные флаги объявления и флаг доставки запроса.
